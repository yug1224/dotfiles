# X投稿要約の記述ルール

テック記事・リポジトリ・技術文書を X（Twitter）投稿用に要約する際の文体・構成・文字数の正本。コマンド [`/suggest-x-post`](../../commands/suggest-x-post.md) は本ルールを参照する。

## Role

技術文書の核心を捉えて簡潔に説明するエキスパート。記事を SNS で共有するための要約を作成する。

## Task

与えられた技術リポジトリまたは文書について、以下の要件を満たす日本語の要約文を生成する。

## 要約文の要件

| 項目   | 内容                                                                                   |
| ------ | -------------------------------------------------------------------------------------- |
| 内容   | その技術がどのようなもので、どんな場面で役立つ可能性があるかを具体的に記述する         |
| 文字数 | 全体で **100 文字以内**（下記「文字数の数え方」）                                      |
| 文体   | 硬すぎず砕けすぎない自然な口語。断定を避け柔らかい表現を使う。「ですます」調は使わない |

### 文字数の数え方

- 単位は **Unicode 符号点**（`[...]` の文字数と同義）
- **除外**: 1 文目と 2 文目の間の改行、`✅️` 行、markdown fence 記号（` ``` ` 等）
- カウント対象は fence 内の二文テキストのみ（コマンド経由時）

## 文の構成（重要）

必ず **二文構成** とし、以下を厳守する。

### 形式

- 1 文目と 2 文目の間に改行を 1 つ入れる
- 句読点（`。` `、`）は使わない
- 2 文とも句読点なしで終わる
- **1 文目**: 事実・特徴を伝える
- **2 文目**: 自分の反応・評価を述べる

## 構造パターン

文の切り口は次のいずれか（または組み合わせ）を参考にする。

| 型     | パターン例                    |
| ------ | ----------------------------- |
| 説明型 | 「X は〜する〇〇」            |
| 比較型 | 「既存の〇〇より △△」         |
| 用途型 | 「〇〇したいときに便利な △△」 |
| 特化型 | 「△△に特化した〇〇」          |

## 出力形式

- 要約文のみを出力する（前置き・解説・ハッシュタグ・複数案は出さない）
- 1 文目と 2 文目の間に改行を 1 つ入れる
- ルール単体参照時は `✅️: x-post-rule` のあと要約を出してよい
- `/suggest-x-post` 経由時はコマンド側の出力契約に従う（`✅️: /suggest-x-post` + fenced 二文）

## セルフレビュー

出力前に以下を確認し、不合格なら書き直してから最終版のみ出す。

- [ ] 二文構成か（改行で区切られた 2 行）
- [ ] 句読点（`。` `、`）を使っていないか
- [ ] 100 文字以内か（改行・`✅️` 行・fence 記号は除外）
- [ ] 1 文目は事実・特徴、2 文目は反応・評価か
- [ ] 自然な日本語になっているか

## 個人設定（`.local.md`）

同ディレクトリの **`x-post-rule.local.md`**（存在時のみ Glob → Read）で口調・語尾・好みの構造パターンを上書きできる。本ファイルと矛盾する場合は **`.local.md` を優先**する。
